# ADR-0001: Record architecture decisions

**Status:** Accepted

**Context:**
{{PRODUCT_NAME}} will accumulate significant technical decisions (stack, data model, integrations,
hosting). Without a durable record, the reasoning behind each decision is lost, decisions get
re-litigated, and new contributors (human or agent) can't tell deliberate choices from accidents.

**Decision:**
We record every significant architecture decision as an Architecture Decision Record (ADR) in
`documents/architecture/decisions/`, one file per decision, named `NNNN-short-title.md` with a
monotonically increasing number. Each ADR states its status (Proposed / Accepted / Deprecated /
Superseded), the context, the decision, alternatives considered, and consequences. A decision is
not "made" until its ADR is **Accepted**. Superseding decisions get a new ADR that links back to
the one it replaces.

**Alternatives Considered:**
1. Decisions in a single running document — rejected: grows unwieldy, no per-decision status, hard to link.
2. Decisions only in commit messages / chat — rejected: not discoverable, no alternatives or consequences captured.

**Consequences:**
- Positive: decisions are discoverable, reviewable, and survive team/agent turnover; agents can check intent before changing architecture.
- Negative: small writing overhead per decision.
- Risks: ADRs go stale if status isn't maintained — mitigated by the SYNC workflow updating statuses.
