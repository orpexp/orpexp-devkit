# Claude Code Guide

Everything about the tool itself: concepts, first run, CLI reference, permissions, CLAUDE.md, and MCP.
For *which skill to use when*, see the [Product Workflow](02-product-workflow.md) and [Skills & Agents](03-skills-and-agents.md) guides.

---

## What Claude Code is

Claude Code is an AI coding agent in your terminal. It reads your project files, understands your
codebase, and takes real actions — writing code, running commands, searching docs. When you ask it
something, it reads the relevant context, thinks, acts, and reports back. It's not a chatbot — it's
an agent that does work.

**Good at:** exploring unfamiliar codebases, implementing features end-to-end, debugging with
context, refactoring, writing tests, code review, architecture discussion, documentation.

**Needs you for:** business decisions (tell it what you want, not just what you have), verifying UI
in the browser, your preferences (state them in `CLAUDE.md` or the prompt), very large one-shot
changes (break them into steps).

## First run

```bash
cd my-project
claude
```

1. **New product?** Run `/product-init` with your idea notes — it generates the full structure
   (`CLAUDE.md`, `.ai/`, `documents/`, `platform/`). **Existing plain repo?** Run `/init` for a
   starter `CLAUDE.md`.
2. **Orient Claude:** `"Give me an overview of this codebase. What does it do and how is it structured?"`
3. **Pick a role:** start tasks with a skill (e.g. `/product-owner`, `/architect`) to get
   role-appropriate output — see [Skills & Agents](03-skills-and-agents.md).

## CLI entry points

```bash
claude                                  # interactive session in current directory
claude -p "explain the auth flow"       # one-shot prompt, no session
claude --continue                       # continue the most recent conversation
claude --resume                         # resume a specific past session
claude --model claude-opus-4-8          # start with a specific model
claude --version
```

## In-session slash commands

| Command | What it does |
|---|---|
| `/help` | Show all available commands and skills |
| `/clear` | Clear conversation history, start fresh |
| `/compact` | Summarize the conversation to free context |
| `/status` | Current model, memory usage, active MCP servers |
| `/memory` | View and edit Claude's persistent memory |
| `/init` | Initialize a starter CLAUDE.md in the current directory |
| `/settings` | Open settings editor |
| `/model` | Switch the active model |
| `/mcp` | List active MCP servers and their tools |
| `/code-review` | Review current branch changes (`ultra` = deep multi-agent review, billed; `ultra <PR#>` = review a GitHub PR) |

## Permission modes

Claude Code asks before taking certain actions. Set the default in `~/.claude/settings.json`:

| Mode | Behavior | Use |
|---|---|---|
| `default` | Asks before reads, edits, and commands | Most cautious |
| `acceptEdits` | Auto-approves reads/edits; asks before shell commands | **Recommended for most work** |
| `bypassPermissions` | Auto-approves everything | Only CI/CD or sandboxed environments |

```json
{ "defaultMode": "acceptEdits" }
```

Review diffs before approving large edits regardless of mode — Claude shows you what it's about to do.

## CLAUDE.md — project context

`CLAUDE.md` files are loaded automatically when Claude starts in that directory:

```
~/.claude/CLAUDE.md        ← global (applies everywhere; this repo's global/CLAUDE.md is a template)
my-project/CLAUDE.md       ← project root (auto-loaded)
```

**This framework's convention — the thin pointer.** Projects generated by `/product-init` keep the
root `CLAUDE.md` at ~3 lines; it `@`-imports the canonical, tool-agnostic context:

```markdown
# CLAUDE.md
The canonical working context for this repo lives in [.ai/AGENTS.md](.ai/AGENTS.md).
@.ai/AGENTS.md
```

Keep all substantive guidance (stack, conventions, behavioral rules, reading order) in
`.ai/AGENTS.md` — never duplicated into the root file. That's how `.ai/` content reaches Claude
while staying useful to any other tool or human.

## Sessions & context

- Conversation history persists within a session; `claude --continue` resumes the last one.
- Use `/compact` when a session gets long to free context.
- For project memory across sessions, rely on the framework's files, not the conversation:
  `.ai/AGENTS.md` (rules + reading order) and `documents/operations/01-progress.md` (current state).
  See [Product Workflow → Managing context](02-product-workflow.md#managing-context-across-sessions).

## MCP servers

MCP servers add external tools to Claude Code (databases, APIs, design tools):

```bash
claude mcp add <name> <command> [args...]   # add
claude mcp list                             # list
claude mcp remove <name>                    # remove
```

**Recommended servers for this framework's workflow:**

| Stage | MCP server | What it unlocks |
|---|---|---|
| Design | Figma | `/design-review` and `/designer` read frames directly instead of pasted screenshots |
| Build | Postgres (or your DB) | `/backend-dev` and `/architect` inspect the live schema |
| Review / Ship | GitHub | `/scrum-master`, `/code-review`, and `progress-tracker` read issues and PRs |

## Tips for effective use

**Be specific:**
```
❌ "Fix the login"
✓ "POST /api/auth/login returns 401 with correct credentials.
   Look at src/app/api/auth/login/route.ts and find what's wrong."
```

**Give context before asking** — name the files, the stack, and the goal in the prompt, or better:
keep them current in `.ai/AGENTS.md` so every session starts oriented.

**Reference files explicitly:** `"Look at src/lib/auth.ts and explain the token refresh logic"`.

**Iterate in small steps** — "data model → API → UI component → wire it up" beats "build the whole
checkout flow". `/build-plan` generates exactly this sequence for you.

**Use roles and chains** — the right skill per stage, with handoffs through `documents/`. That's
the subject of the [Product Workflow guide](02-product-workflow.md).
